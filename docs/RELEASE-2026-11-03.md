# Journal de livraison : plateforme WarsNuto

## Réalisé

- Site existant conservé ; état de départ sauvegardé dans le commit `861e1e6`.
- Connexion OAuth Discord avec PKCE, state à usage unique et scope identify.
- Comptes personnels, informations Discord, préférences et sessions révocables.
- Sessions persistantes : deux heures maximum, trente minutes d'inactivité.
- Rôles USER, MODERATOR, ADMIN et OWNER, contrôlés côté serveur.
- Premier propriétaire par CLI contrôlée ; dernier propriétaire actif protégé.
- Administration : comptes, recherche, rôles, suspensions, permissions, journal et paramètres.
- Confirmations des opérations, contrôle de versions et transactions SQL.
- Passerelle Vercel HTTPS limitée aux routes de la plateforme ; configuration absente = refus.
- Construction statique par allowlist, sans publication de base, backend ou environnement.
- Interface mobile et ordinateur avec icônes Lucide et thème WarsNuto conservé.
- Documentation, exemple d'environnement sans secrets et CI Linux Node 24.

## Vérifications locales exécutées

- 60 tests Node réussis, aucun échec ni test ignoré : 42 nouveaux scénarios et 18 régressions publiques.
- 26 scénarios navigateur réussis, répartis entre ordinateur et mobile.
- Contrôle de syntaxe JavaScript et JSON Vercel réussi.
- Construction statique réussie ; sous-ensemble d'icônes d'environ 11 ko.
- Audit npm : aucune vulnérabilité connue au moment du contrôle.
- Captures des principales pages inspectées, sans débordement horizontal du document.

Les identités et chiffres visibles dans les captures de test sont des fixtures,
pas des comptes réels. Aucune base des bots ni aucun vrai compte Discord ne sert
de fixture. Les captures et traces ne sont pas publiées dans Git.

## Non activé / non vérifié en production

- Secrets OAuth et session non renseignés par cette livraison.
- Backend non installé ni démarré sur Hetzner ; aucun bot redémarré.
- DNS, certificat et reverse proxy de l'origine web non modifiés.
- Connexion Discord réelle et trajet Vercel vers le backend à recetter après configuration.
- Connecteurs Game/Protect/Support non activés, sans statistiques ou sanctions inventées.
- Aucun test d'endurance ni preuve de capacité à 130 000 connexions simultanées.
- Pas de second facteur propre au site ; activer la 2FA Discord des administrateurs.

Les instructions et la liste des variables par hébergeur sont dans [PLATFORM.md](PLATFORM.md).
Le code est livré sur une branche dédiée ; un push ne remplace pas l'autorisation
de bascule de production ni la configuration de l'infrastructure.
