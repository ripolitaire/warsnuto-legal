# Refonte WarsNuto Univers

## Cadre

Branche : `rework/community-platform-20261116`. Travail local uniquement, sans
deploiement, sans migration de donnees et sans modification des bots.
Les changements deja presents dans le depot sont conserves.

## Audit initial

- Frontend : HTML, CSS, JavaScript natif ; icones Lucide compilees par esbuild.
- Backend : Express 5, SQLite dedie au site, OAuth Discord via oauth4webapi.
- Public : accueil, Discord, YouTube, trois bots, documentation, catalogue,
  confidentialite et conditions. Routes existantes a conserver.
- Prive : profil, preferences, XP Protect, progression Game, collection,
  serveurs, recrutement. Administration : configuration, supervision, comptes,
  permissions, journal, prisons et candidatures.
- Integrations : API publiques separees pour Discord et YouTube ; connecteurs
  prives aux bots par sockets Unix. Identite issue de la session, jamais du navigateur.
- OAuth : PKCE S256, etat a usage unique lie au navigateur, cookies signes
  HttpOnly/SameSite, Secure en production ; jetons Discord non conserves.
- Sessions : expiration absolue et inactive, revocation, CSRF + controle Origin,
  reauthentification recente pour les mutations sensibles. Permissions verifiees
  cote serveur et controles propres aux bots. Ne pas remplacer ces mecanismes.
- Catalogue : 205 cartes, 9 raretes, 5 Royale ; illustrations completes et miniatures.
  SHA256 catalogue initial : `BA93D0C5A2B79C5D47BC3DF83D0EB8C5C4026AF3AB192268E0FF9499916071BB`.
- Game : cartes et Arcade presentes ; aventure One Piece en maintenance.
- Base tests : 128 reussites, 2 tests Linux ignores sous Windows, aucun echec.

## Problemes constates

1. Navigation publique variable ; collection absente du menu de compte.
2. Accueil repetitif, ancien RPG encore presente comme fonctionnalite principale.
3. Styles publics et prives cumulatifs, gros arrondis et sections trop encadrees.
4. Catalogue non servi par Express local ; script cards.js absent de l'allowlist.
5. Filtres catalogue non partageables, fermeture de detail et etats vides rudimentaires.
6. Profil charge les deux integrations en serie ; collection trop peu visible.
7. Menus prives trop longs sur telephone ; pas de lien d'evitement.
8. Chargement YouTube sans delai maximal et sans reprise manuelle.

## Plan priorise

1. Unifier les tokens visuels et le chrome public/prive sans toucher aux droits.
2. Recomposer accueil et Game avec les images existantes et des liens directs.
3. Moderniser catalogue et collection, conserver exactement donnees et probabilites.
4. Ameliorer profil, menus mobiles, formulaires, tableaux et retours d'erreur.
5. Verifier tous les parcours publics et prives, les permissions et le build.
6. Livrer un rapport de verification et les instructions de publication, sans publier.

## Verification et limites

### Livraison locale

- Accueil recompose : illustration pleine largeur, entree Game, apercu de vraies
  cartes, videos, trois dernieres publications datees et services essentiels.
- Navigation publique commune : Accueil, Game, Collection, Communaute, Bots,
  Documentation ; YouTube et liens legaux accessibles depuis le pied de page.
- Catalogue : recherche, rarete, univers, pagination et fiches partageables par
  URL ; fermeture clavier, retour du focus, reinitialisation des filtres.
- Collection privee : serveur, univers, cartes possedees/manquantes/doublons,
  nombre d'exemplaires, progression globale et par rarete. Source propre au compte.
- Game : cartes, echanges et Arcade distincts de One Piece en maintenance ;
  anciennes mentions contradictoires corrigees, aucune regle de jeu changee.
- Profil : acces direct a la collection ; lectures Protect/Game simultanees et
  requetes GET identiques partagees seulement pendant leur execution, sans cache
  persistant de donnees privees et sans melange des generations de session.
- Administration, recrutement, preferences et pages legales harmonises :
  surfaces communes, formulaires lisibles, menu mobile, tableaux et confirmations
  existantes conserves. Aucun changement de la hierarchie des autorisations.
- Documentation repartie en rubriques repliables. Une grande section ne peut
  plus rester invisible a cause du seuil de l'IntersectionObserver.
- YouTube : timeout de 8 secondes, reprise manuelle, requetes concurrentes evitees.
- Les compteurs de l'accueil exigent une source Discord live recente ; un ancien
  snapshot n'est pas presente comme une mesure actuelle.
- Correction du service local du catalogue et des styles inline de la page
  de connexion a la collection, auparavant bloques par la CSP.
- Textes francais, metadonnees, espacement et typographie harmonises ; pas de
  taille de police indexee sur la largeur du viewport ni d'interlettrage negatif.

### Design system

`theme.css` porte les tokens : fond #0c0d10, surfaces #17191f, rouge #e43d45,
or #efc66b, typographie systeme, rayons de 4 a 8 px, controles de 42 px minimum.
Les variantes clair/systeme, densite et mouvements reduits restent disponibles.
`community.css` est la couche partagee de presentation publique et privee ;
`community.js` gere les menus, liens d'evitement et pied de page commun.
Les modules de configuration, recrutement et moderation gardent leur logique
et leurs connecteurs. Les illustrations viennent des assets existants.

### Resultats

- `npm test` : 132 tests, 130 reussis, aucun echec, 2 ignores sous Windows
  (socket Unix et protection symlink a reexecuter sous Linux).
- `npm run test:browser` : 134 reussites, Chromium desktop et mobile.
- `npm run check` : 82 fichiers JavaScript analyses, JSON Vercel valide.
- `npm run build` : 29 fichiers publics et assets ; aucun backend, .env ou base
  dans dist. La nouvelle couche partagee est dans l'allowlist.
- `git diff --check` : aucun probleme d'espacement.
- Catalogue SHA256 final identique a l'empreinte initiale ci-dessus.
- Captures automatiques : public, collection, profils, preferences, configuration,
  recrutement et administration dans `test-results/` (dossier ignore par Git).
- Controles complementaires des pages accueil/catalogue/docs a 360, 768 et
  1920 px : aucun debordement horizontal. Captures dans `artifacts/` (ignore).

Les scenarios connectes utilisent une base en memoire, un fournisseur OAuth de
test et des connecteurs de test. Ils ne lisent pas le .env de production et
n'ecrivent pas dans les bases reelles. La connexion OAuth reelle, les sockets
des bots sur Linux et la configuration Vercel/VPS restent a valider apres
autorisation, sur une preproduction. Safari/Firefox ne sont pas certifies par
cette suite Chromium. Aucun audit automatise ne garantit l'absence de toute faille.

## Apercu et publication

`npm run preview` ouvre le public sur http://127.0.0.1:4318. Port alternatif :
`npm run preview -- 4319`. Ce processus utilise SQLite en memoire, ne charge aucun
.env et ne configure pas OAuth : aucun compte fictif n'est propose a l'utilisateur.
Les API publiques conservent leurs sources habituelles ; une panne amont est affichee.

Avant une publication explicitement autorisee :

1. Faire valider les pages sur l'apercu ; examiner le diff de cette branche et
   separer les changements deja presents avant la refonte lors du commit.
2. Refaire `npm ci`, `npm run check`, `npm test`, `npm run test:browser` et
   `npm run build` sous Node 24 sur une preproduction Linux.
3. Sauvegarder la base web et conserver les releases frontend/backend precedentes.
   Aucune migration SQL n'est necessaire pour cette refonte.
4. Publier dist et les API publiques selon le pipeline Vercel existant, puis une
   release backend coordonnee incluant server, community.css, community.js,
   platform.js, cards.css, cards.js, personal-cards.js, assets et les autres fichiers
   publics de l'allowlist. Garder .env, bases, sauvegardes et certificats hors release.
5. Tester OAuth reel, deconnexion, droits membre/staff, collection et connecteurs,
   ainsi que les erreurs amont et les assets ; ne pas redemarrer les bots.
6. En cas de regression, revenir aux releases frontend ET backend precedentes.
   Ne pas restaurer ou supprimer la base : son schema est inchange.

La premiere livraison etait locale, sans publication. Le deploiement a ensuite
ete explicitement autorise et effectue le 16 novembre : voir
[le journal de deploiement](RELEASE-2026-11-16-COMMUNITY.md).
Aucun commit, push ni changement de secrets n'a ete effectue.
